# Sesión 2026-08-03 — Lunes

## Resumen del día

Sesión larga de fixes acumulados y una función nueva completa (sistema de zonas). Se corrigió un bug real de caché de imágenes en el perfil, se re-integró el widget de pantalla de inicio de iOS (se había quitado por completo en una sesión anterior sin darse cuenta de que rompía el widget), se hicieron varias rondas de ajustes visuales en la pantalla de Riders guiadas por capturas anotadas del negocio, se crearon cuentas de prueba para repartidor/flota, se construyó de cero el sistema de **zona** (Maravatío/Acámbaro) con detección automática, se intentó integrar un estilo de mapa gris personalizado (bloqueado por falta de cuenta de facturación en Google Cloud, pausado), se le dio paridad visual y funcional completa a las pantallas de entrega activa de Riders y Flota, se diagnosticó (sin ser bug) una demora de GPS al iniciar la app, se corrigieron contrastes muy pobres en el panel de Dueño, y se reinstaló la app de GOGO Flota actualizada.

---

## Lo que se hizo

### Bug de caché de foto de perfil
- `Image.network(url)` cachea por string de URL — al resubir una foto nueva a la MISMA ruta de Supabase Storage, seguía mostrando la foto vieja
- Fix: helper `_withCacheBust(url)` que agrega `?v=timestamp` a la URL para forzar que no use caché
- También se cambió el nombre del archivo local temporal de uno fijo (`profile_photo.jpg`) a uno único por timestamp, con limpieza de archivos viejos, para evitar el mismo problema de caché con `Image.file`

### Widget de pantalla de inicio (iOS) — reintegrado
- El paquete `home_widget` había sido eliminado por completo en una sesión anterior (se pensó, equivocadamente, que causaba un crash no relacionado) — esto rompió por completo la alimentación de datos del widget `GOGOTrackingWidget`
- Se volvió a agregar la dependencia y el código en `main.dart`, `main_admin.dart`, `main_flota.dart` y `tracking_screen.dart` (`HomeWidget.setAppGroupId(...)` + el envío de datos al `UserDefaults` compartido)

### Ajustes visuales en Riders (repartidor_plus_screen.dart)
- El nombre debe estar **al lado** de la foto de perfil, no debajo — se cambió el header de `Column` a `Row`
- Los logos reales de los restaurantes ahora salen en las tarjetas de pedido (antes solo un ícono genérico) — se expandió el `select` de Supabase para traer `restaurants.image_url`
- El color de las tarjetas de pedido se cambió para que combine con el naranja del header (se había cambiado por error el fondo de toda la pantalla en un primer intento — corregido tras feedback directo)
- Tamaño de las tarjetas de pedido: se agrandó primero para que se pareciera a las de restaurantes, luego se redujo ("más chicos") tras feedback

### Cuentas de prueba creadas
- `rider.prueba@fercadi.com` (repartidor_plus)
- `moto.flota.prueba@fercadi.com` (repartidor, vinculado a una flota vía `flota_members`)
- `flota.prueba@fercadi.com` (jefe_flota)

### Sistema de Zonas (Maravatío / Acámbaro) — función nueva completa
- Primero se amplió el radio de cobertura GPS de 30 km a 50 km para que Acámbaro quedara dentro
- Luego, para que un cliente en una ciudad no viera restaurantes de la otra, se agregó una columna `zona` a `restaurants` con **detección automática** (no botones manuales, corregido tras instrucción explícita): `LocationService.zonaFromCoords(lat, lng)` (Haversine contra los centros de ambas ciudades) y `detectZona(address)` como fallback sin coordenadas
- Cliente: selector de zona consolidado dentro del mismo picker de "Dirección de entrega" en `/profile` (como un 4to `ListTile`, no una tarjeta aparte — corregido para igualar el boceto del negocio)
- Dueño: la zona se calcula sola y se muestra de solo lectura en `/dueno`, ya no hay selector manual
- `restaurants_screen.dart` filtra la lista por zona; se corrigieron dos bugs de propagación (el refresh de zona no llegaba tras volver de `/profile` por el camino del menú hamburguesa, y pull-to-refresh no releía la zona)
- Se aprovechó para arreglar un bug preexistente no relacionado: el mensaje de "no hay restaurantes" nunca se mostraba cuando la lista estaba realmente vacía (`itemCount` mal calculado)

### Otros fixes de UX (perfil / restaurantes / checkout / carrito)
- Pull-to-refresh en la lista de restaurantes
- Alineación del avatar del header con el margen de las tarjetas
- Tamaño de las tarjetas del carrito: se agrandó y luego se redujo ("más chicos") tras feedback
- Etiquetas de los campos del checkout: de "pestaña" cuadrada a completamente redondeadas ("pastillas"), por pedido directo del negocio

### Estilo de mapa personalizado (Google Maps) — pausado
- Se guio la creación de un Map Style ("GOGO Food - Estilo Gris") paso a paso en Google Cloud Console
- Se descubrió que el primer intento se hizo en el proyecto de Google Cloud equivocado (uno sin relación con la app) — se ubicó el proyecto correcto (`proyectocompartido-13288`) y se recreó ahí
- Bloqueado por: el proyecto correcto no tiene cuenta de facturación activa ("Quota status is BLOCKED") — el negocio no puede agregar tarjeta por ahora
- Se quitó el `mapId` del código, se dejó el ID correcto (`c954c88d2bf2e40dd79e55f9`) en un comentario para cuando se resuelva la facturación

### Paridad Riders ↔ Flota en pantallas de entrega activa
- Se agregó mecanismo de cancelar entrega a ambas pantallas (antes solo existía en una), con diálogo de confirmación y `PopScope` bloqueando el gesto de regresar/swipe-back
- Se unificaron colores y estilo del stepper entre `entrega_activa_screen.dart` (Riders) y `repartidor_screen.dart` (Flota) usando las constantes de `AppConstants` como fuente de verdad
- El botón "Cancelar pedido" pasó de un `OutlinedButton` de bajo contraste (rojo sobre naranja) al mismo estilo sólido de alto contraste que ya usaba "RECHAZAR" en otras pantallas

### Diagnóstico de GPS — el ícono de la moto no aparecía
- Investigación extensa con `debugPrint` en vivo (varios ciclos de reinstalación por cable, porque el debug por WiFi se desconectaba constantemente)
- Causa real: **no era un bug** — simplemente el GPS tarda 10-30+ segundos en obtener una posición al abrir la app
- Fix: se agregó un indicador "Buscando tu ubicación..." mientras no hay posición, en vez de más cambios de lógica de permisos
- De paso: se agregaron reintentos automáticos de inicialización de GPS al volver del background (`WidgetsBindingObserver`/`didChangeAppLifecycleState`), y un diálogo propio para reabrir Configuración cuando el GPS del sistema está apagado o el permiso fue denegado permanentemente (iOS no vuelve a mostrar su propio diálogo solo)

### Contraste en el panel de Dueño
- Las tarjetas de estadísticas y los íconos de la barra inferior eran casi invisibles en modo claro contra el fondo naranja (el fondo de la barra inferior es naranja oscuro, no blanco como se podría asumir)
- Fix: fondo de las tarjetas a blanco, texto secundario a negro con opacidad; íconos/texto inactivos de la barra inferior de negro casi invisible a blanco con opacidad

### GOGO Flota — reinstalada
- Se reconstruyó y reinstaló la app separada de Flota (`main_flota.dart`) en el iPhone de angelo tras los cambios de paridad visual
