## Security Review — 3 vulnerabilidades corregidas (`/security-review`)

### Vuln 1 — CRÍTICA: Clave `service_role` hardcodeada en código cliente
- La clave de admin de Supabase estaba incrustada en `supabase_service.dart` como constante estática
- En el build web de Flutter (Vercel), los strings quedan en texto plano en `main.dart.js` — cualquiera con DevTools la podía extraer
- La clave tiene acceso total a toda la BD, bypassea RLS, expira en 2036
- **Fix:** Eliminada la constante hardcodeada; ahora usa `AppConstants.supabaseServiceRoleKey` (vacía por defecto)
- **⚠️ Pendiente:** Rotar la clave en Supabase Dashboard → Settings → API → Regenerate

### Vuln 2 — ALTA: `/flota` sin autenticación + cualquier usuario podía crear cuentas de repartidor
- La ruta `/flota` estaba en el conjunto abierto (sin verificación de sesión)
- Un usuario cliente con sesión válida podía abrir la pantalla y crear cuentas de repartidor usando la clave admin embebida
- **Fix:** `/flota` movida a rutas protegidas con guardia `role == 'jefe_flota'`; FAB oculto cuando `_jefeId == null`

### Vuln 3 — MEDIA: Stats del rider escritas directamente desde el cliente
- `incrementRiderStats` hacía read-modify-write desde el cliente: leía el saldo, sumaba localmente y escribía el total
- Un rider malicioso podía extraer el anon key del APK y hacer un PATCH directo a Supabase con el saldo que quisiera
- **Fix:** Cambiado a llamada RPC atómica `increment_rider_stats(p_rider_id, p_coins_add, ...)` que corre en el servidor
- **⚠️ Pendiente:** Ejecutar una vez el SQL de la función en Supabase → SQL Editor (ver comentario en `supabase_service.dart`)
